# 本机演示说明

## 提前准备

- 在正式项目根目录运行 `.\.venv\Scripts\python.exe web_app.py`。
- 打开 `http://127.0.0.1:8000/api/health`，确认状态及北京时间；再打开首页。
- 保留现有 `.venv`、`data`、模型权重和报告；不为整理目录清空它们。
- 面试前自己检查一份已完成调查：问题、目标更新、来源、原文和结论是否一致。旧失败记录可以保留，不要拿它冒充成功演示。
- 准备一段实际操作录屏作网络故障兜底；本次目录整理不包含录制视频。

## 3—5 分钟展示顺序

1. 首页说明任务及三类来源，打开一份自己核对过的历史调查。
2. 展示工具轨迹、分段结论、范围限制和完整报告。
3. IDE 打开 `gamelens/core/runtime.py` 的 `_build_graph`，讲决策/执行/修复/结束。
4. 打开 `gamelens/rag/tools.py` 与 `index.py`，讲过滤、双路召回、融合、筛选。
5. 打开 `tests/test_unified_retrieval.py` 的一个边界测试，再看实测摘要。

历史查看和文件阅读不需要新模型请求。现场新建调查可能消耗 API、读取 Steam 并遇到限流，只有明确准备好额度、网络和审批时再做；不能保证外部服务可用。

## 启动失败时

- 核对工作目录、解释器和 8000 端口占用，阅读具体报错。
- 不删除 `.venv` 或重新采集数据作为第一反应。
- 不结束不属于本项目的 Python 进程。
- 无网络时先展示保存结果和代码，明确是历史运行，不伪装成实时结果。

## 仓库展示边界

本机文件目录不等于已发布 GitHub 仓库。上传前另外检查密钥、历史提交、玩家身份、私有响应及本地路径；`.gitignore` 不能清除已经跟踪的敏感文件。
