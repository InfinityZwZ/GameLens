# 评测复现与资料范围

## 仓库里可以验证什么

保留源码、测试及 `evals/fixtures`、`evals/retrieval` 等合成夹具。安装已有依赖后可运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe evaluate.py --mode offline --output-dir evals/results/local-offline
```

输出目录使用新名称，不覆盖历史结果。这是实现/契约回归和合成资料验证，不是正式真实玩家 Benchmark 的重跑。

## 真实评测为何没有整包上传

正式真实包含 Steam 评论、公告讨论资料、来源映射和私有轨迹，保存在作者本地；仓库不分发这些未经逐项公开审核的原件，也不隐式抓取新数据替代它们。合成资料不能复现真实冻结包的 Recall 数字。

原实验包含 40 检索题、25 有效调查题；原文哈希、审核、固定时钟、配置、模型 revision、逐题排名与账本保留本地。缺少该包时真实评测应明确阻塞，不伪造或静默替换数据。开源代码可查看 `benchmark.py` 和 `gamelens/evaluation`。

## 正式评分层次

- 检索：Recall@5/10、MRR@10、nDCG@10、无答案误返回、支持/反例覆盖及分阶段耗时。
- 工具 Oracle：给定已审核计划后核对工具与事实，不测自主规划。
- Agent：自己选择行动后接受数字、时间、人群、来源和引用硬检查。
- AI 评委：相关性、证据支持、范围、完整性、可读性各 0—2，理由与依据须核验；总分至少 8 且证据/范围都为 2、无严重错误，仍不能覆盖硬检查失败。

同模型评分、小样本和内部留出有局限；未完成、无法判断、调用失败和业务失败分别统计。不得把保存记录混成当前模型统一准确率。

## 真实调用

Agent、Screening 和 Judge 可能产生费用；必须显式允许并限定 HTTP 总预算。此仓库展示准备没有新增模型请求、Steam 采集或模型下载。固定工作流付费对比和检索 Screening 不能冒称已测。
